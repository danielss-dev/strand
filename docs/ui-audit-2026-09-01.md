# Strand UI/UX audit — 2026-09-01

Visual and interaction audit of Strand 1.5.0 (dev build, Windows 11, 1440×920 CSS px, dark theme, amber accent, default density unless noted).

**Method.** The app was driven over CDP (`--remote-debugging-port`, isolated WebView2 profile, `window.__strand` store hook) and screenshotted across every view, both themes, both non-default densities, the palette, dialogs, context menus, and hover states. In parallel, three code audits covered the persistent chrome (`Topbar`, `Sidebar`, `RepoRail`, `RepoTabs`, `StatusBar`, `chrome.css`), the main-pane views (`LocalChanges`, `Commits`, `CommitDetail`, `Review`, `WorkspaceReview`, `Work`, `FileView`, `PullRequests`, `Worktrees`, `Reflog`, `Diff.tsx`, `PierreTree`), and the dialogs / settings / palette plus `features.css` health. Every finding below is backed by a screenshot in `ui-audit-2026-09-01/` or a file reference.

Nothing in the codebase was changed as part of this audit.

---

## 1. Summary

The foundation is good: warm OKLCH palette, a real token system (`tokens.css`), Geist + JetBrains Mono, a strong command palette, clean simple dialogs. The problem is growth: the app has accumulated features faster than the visual system, and three themes explain most of what follows.

1. **Several visual languages coexist.** Dense tables (Commits, Local Changes), a padded accent bar (Review), a marketing-style hero (Worktrees, Pull Requests), and a chat app (Workbench / Heroi) live behind the same sidebar with no shared header, toolbar, or empty-state primitive.
2. **Tokens exist but are bypassed.** `features.css` is 246 KB / ~9,700 lines with ~300 hardcoded `font-size: Npx` vs 92 `var(--type-*)` uses; 242 `border-radius` declarations of which 40 use `--r-*`; 14 distinct z-index values; 15 transition durations; 59 hardcoded colours outside `tokens.css`. Density and radius can't scale because most of the UI isn't wired to them.
3. **Navigation and information are duplicated.** Branch + ahead/behind appear in three places; worktrees in three; fetch/pull/push in two; stash in two; the repo rail and repo tabs are near copy-pastes of each other.

## 3. Improvements, ranked by impact

### A. Visual cohesion (highest leverage)

**1. Unify the main-pane header/toolbar primitive.**
Today: `.lc-col-head` is 34px uppercase (`features.css:590–604`), `.graph-toolbar` is 36px plain (`890–898`), `.rv-toolbar` is padding-only with an accent tint (`5462–5469`), `.pr-toolbar` is a two-row affair, Worktrees is a hero (`Worktrees.tsx:409–464`). Button styles for the same job: `.h-link`, `.btn ghost`, `.icon-btn`, `.search-nav`. One `PaneHeader` with a fixed height, one label style, and one button style would make every view feel like the same app.

Worktrees and Pull Requests use 28–32px display titles, kicker text, stat cards, and a hero-sized search input, while Commits / Local Changes / Review are 12px dense tables. Pick one register (dense, tool-like) and bring PR and Worktrees down to it. The PR list also renders two header rows (breadcrumb row, then "Updated just now / Refresh / Create PR") before the title.

**2. Theme the Pierre diff surface.**
The diff container is Pierre's default `--diffs-bg: light-dark(#fff, #0a0a0a)` — a cold neutral black inside a warm-charcoal app (`--bg-base` is `oklch(0.185 0.007 65)`). The seam is visible at the file-list / diff boundary, and the hunk-hover highlight is Pierre's default blue, off-palette for the warm theme. The "N unmodified lines" pill is neutral gray too.

![Diff seam](ui-audit-2026-09-01/30-diff-seam-zoom.png)
![Hunk hover](ui-audit-2026-09-01/29-diff-hunk-hover.png)

Fix: map `--diffs-bg`, gutter, and hover/selection to `--bg-base` / `--gutter` / `--selection` in `Diff.tsx` `diffAppearanceOptions` (lines 55–66).

**3. Make density actually work.**
Compact density only tightens the sidebar; the Local Changes file rows and diff are pixel-identical in default vs compact (compare `02-local-changes.png` with `34-compact-local-changes.png`). The commit graph uses its own `ROW_PX` 26/32/38 (`Commits.tsx:31`) instead of `--row-h` 22/26/32 (`tokens.css:8–40`), and `CommitGraphCell` has a fixed 32px viewBox with `preserveAspectRatio="none"` (`CommitGraphCell.tsx:11,28`), so lane geometry distorts in the other two densities. Topbar (44px), sync/branch/cmd controls (28px), status bar (24px), and main header (38px) are all fixed (`chrome.css:64, 394, 535, 587, 1235, 1350`).

**4. Adopt the radius and type scales.**
Chrome uses 3, 4, 6, 7, 8, 9, 10, 11, 12, 13px radii; tokens define 4/6/10/14 (`tokens.css:17–20`). Font sizes run 8–28px in 20 distinct values. `--text-1` is referenced six times (`chrome.css:856`, `features.css:793, 2737, 2835`) but is not defined in `tokens.css` — those elements silently fall back to inherited colour. The dialog shell itself uses `12px` rather than `--r-xl` (`features.css:3430`).

**5. One empty / loading composition.**
PR, Review, Worktrees, Reflog, and Work have good icon + title + hint empties. Commit Detail (`"Loading…"`, `"No file changes."`, `CommitDetail.tsx:407–448`), Local Changes lists (`"Nothing staged."`, `LocalChanges.tsx:767`), `PierreTree` (`.tree-empty`, dim 12px text, `features.css:7511–7515`), Merge Resolver, and Rebase Editor are bare strings. Expanding an empty Git sidebar section (Tags, Submodules) shows only a header with `0` (`Sidebar.tsx:1082–1185`). Skeletons: Local Changes uses fixed-height placeholders, PR a spinner, most lists just swap text. Extract one `EmptyState` component and one skeleton style.

**6. One chip / badge taxonomy.**
`.ref-chip` (4px radius, mono, `features.css:1528`), `.pr-state` (999px pill, 9px uppercase, `6045`), `.wt-tag` (5px, 10px uppercase, `8497`), `.det-chip` (9.5px, `chrome.css:571`), `.badge` (accent pill, `984`), `.side-section .count` (mono muted, `1058`), `.sync-btn .count` (`426`), plus the `AI` chip in the graph. Two families would cover it: a ref/mono chip and a status pill.

**7. Cut the topbar down.**
In tabs mode it carries: sidebar toggle, workspace switcher, N repo tabs, `+`, Fetch, Pull, Push, network ▾, Stash, stash ▾, Branch, Quick Launch, and three caption buttons in one 44px strip (24px controls on mac) — 12–15+ controls before counting tabs (`Topbar.tsx:184–323`). Candidates to drop or move: the `↓ 0 ↑ 0` counts when zero (show only when non-zero), the stash count, and possibly the branch switcher since the status bar already shows the branch.

**8. De-duplicate branch / sync.**
Ahead/behind shows in the topbar as `↓ 0 ↑ 0` (down first, muted) and in the status bar as `0↑ 0↓` (up first, green/red even at zero — an alarm colour on a null state; `StatusBar.tsx:32–33` inline colours). Sidebar branch rows also show drift (`Sidebar.tsx:1409–1413`). Pick one home and one order; colour only when non-zero.

**9. Status bar noise.**
`UTF-8 · LF` is shown with no file open and appears static; `1 modified · 0 staged` duplicates the sidebar badge. Long branch names in `.branch` have no `max-width` / ellipsis (`chrome.css:1377–1380`) and will push the right segments off.

**10. Sidebar layering.**
Workspace → repo rail/tabs → primary views (5) → Git/Files tabs → six ref sections (four expanded by default, `Sidebar.tsx:283–285`) → Files tree. Worktrees appear both as tiles in the rail/tabs (`RepoRail.tsx:128–131`, `RepoTabs.tsx:196–199`) and as a Git section (`Sidebar.tsx:1082–1103`). Consider collapsing Tags/Submodules by default and aligning section headers with menu section headers (0.08em vs 0.5px tracking on the same 10px uppercase style; `chrome.css:999–1008` vs `features.css:2786–2791`).

**11. Focus-visible gaps.**
For a "keyboard-first" app, `.sync-btn`, `.branch-btn`, `.cmd-pill`, primary `.side-row`, `.side-tab`, `.rail-tile`, `.tab-add`, `.ws-switch`, and most status items have no `:focus-visible` rule; only `.repo-x`, `.ss-action`, `.sb-gear`, and menu `.x` do (`chrome.css:271, 1043, 1398`). Disabled `.sync-btn` isn't dimmed (`base.css:31` sets only cursor); the branch button uses inline `opacity: 0.5` instead (`Topbar.tsx:648`).

**12. Local Changes header icon row.**
Six unlabeled icon buttons at the far right (two layout toggles, an `×`, refresh, terminal, external). The `×` reads as "close" but sits next to layout toggles; it needs a label or a different home.

![Local Changes toolbar](ui-audit-2026-09-01/27-local-changes-toolbar-zoom.png)

### C. Main views

**13. Commit Detail action overload.**
Checkout, Tag, Cherry-pick, Revert, Rebase from here, Copy subject, Copy body (and more) as equal-weight ghost buttons in two wrapping rows above the file list (`CommitDetail.tsx:290–402`). Keep 2–3 primary actions and put the rest under one `…` menu. The detail panel is also the only pane without a resize handle (`.commit-detail`, `features.css:1341–1352`).

**14. Commit graph rows.**
The message cell carries ref chips + `AI` chip + merge glyph + subject in one ellipsizing cell; long remote-branch chips (`origin/developements/squash-merged-branch-cleanup-61da`) eat most of the width. Author column is `nowrap` without ellipsis (`features.css:1295–1298`). Avatar CSS exists (`features.css:1311`, hardcoded `oklch(0.15 0 0)`) but no avatars render (`Commits.tsx:1244–1245`) — ship avatars or delete it. Consider truncating chips to the last path segment with the full ref on hover.

**15. Workbench / Heroi as the startup surface.**
The default view is a two-column AI chat plus an empty document pane, with git content behind the sidebar. That is a product call, but visually it has the most defects in the app right now:

![Heroi composer](ui-audit-2026-09-01/21-heroi-composer-zoom.png)
![Heroi header](ui-audit-2026-09-01/22-heroi-header-zoom.png)

- Composer footer: the four `<select>`s (Codex / GPT-5.6-Luna / Medium / Build) are too narrow, so the chevron glyph overprints the label text; Send's shortcut label overflows the button; the cwd chip truncates to `m…`.
- Thread header: the provider/model label wraps to three lines inside a 40px header (`Codex · GPT-5.6-Luna`), and the branch chip truncates to `m…`.

**16. Diff capability lottery.**
Minimap and ⌘F diff search exist only in Review / Workspace Review (`Review.tsx:1144+`); PR review reimplements its own split/stacked toggle in its file header (`PullRequests.tsx:1614–1645`) while the global main header already has one (`App.tsx ~2784`); Commit Detail has neither (`CommitDetail.tsx:443–444`). The `'stacked' | 'split'` → Pierre `'unified' | 'split'` mapping is repeated at each call site. Extract one `DiffChrome` (header, layout toggle, search, minimap) and use it in all five places.

**17. Destructive-action model.**
Discard is a double-tap `d` toast in Local Changes (`LocalChanges.tsx:353–356`), an arm-then-"Really discard N files?" link in Review (`Review.tsx:813–828`), an inline confirm pair in Worktrees, a context-menu confirm for stash drop, and an alertdialog for force-push. `.btn.danger` is text-only (`chrome.css:1442`: `color: var(--del)`), so Force push / Hard reset / Clear selected look quieter than a normal primary. One pattern, one filled danger button.

**18. Two toast systems.**
Local Changes / Review / Workspace Review render their own in-view `.toast` with hardcoded hex fallbacks (`var(--del, #e5534b)`, `LocalChanges.tsx:355–361`, `Review.tsx:1196–1204`, `WorkspaceReview.tsx:934–942`); everything else uses `onToast` → `ToastViewport`. Same severity, different look and position.

### D. Dialogs, settings, palette

**19. Extract a `Dialog` component.**
26 modals hand-roll `palette-backdrop → clone-dialog → clone-head/body/foot` (shell: `features.css:3425–3438`), each with its own copy-pasted Tab trap. The traps disagree on what is focusable (Clone omits `select` / `textarea`, `CloneDialog.tsx:52–54`; ForcePush is buttons-only, `ForcePushDialog.tsx:40`; Settings is complete, `SettingsDialog.tsx:72`), and `WorktreeCompareDialog`, `RepoIconDialog`, and `WorkspaceManagerDialog` declare `aria-modal` with no trap at all. Widths are 440 / 460 / 520 / 660 / 680 / 760 / 920 / 1120px, and `stash-dialog` is used as a width mixin by unrelated dialogs (`ForcePushDialog.tsx:58`). Esc-while-busy is blocked in most write dialogs but not in Clone / Settings / ForcePush / RepoIcon / WorkspaceManager. The dialogs *look* fine — this is about stopping the drift.

Near-duplicate clusters: name/path forms (Branch, Tag, RenameBranch, RenameFile, Ignore, FileEntry); path pickers (Clone ↔ InitRepo); radiogroup confirms (Merge ↔ Mainline ↔ Reset); Worktree trio; destructive (ForcePush ↔ BranchCleanup ↔ BranchNetwork force); overlays (Palette ↔ RepoSwitcher).

**20. Settings dialog.**
The frame is small (~540×380 at a 920px window) for 11 sections with 5–8 controls each, so Appearance already scrolls. Give it a larger fixed size. Control vocabulary is split: `SegRow` / `CheckRow` / `SelectRow` in Appearance / Diff, raw `clone-input` + explicit Save in Git (`GitSection.tsx:66–78`), a unique `settings-switch` toggle in Hosting (`HostingSection.tsx:251`), custom rebinding UI in Keyboard.

**21. The palette is the best surface in the app.**
Keep it as the reference for spacing, grouping, and kbd hints. The `repo-menu` vs `context-menu` split (`features.css:2713–2875`) should collapse into one menu style that matches it.

### E. Concrete bugs and polish found in screenshots

- `⌘⇧T` hardcoded in Settings → Appearance on Windows (`AppearanceSection.tsx:101`); `⌘O` hardcoded in `RepoRail.tsx:294`, `RepoTabs.tsx:444`, `Sidebar.tsx:1432`. Quick Launch does it right (`Ctrl K`).
- `1 files with changes` (`App.tsx:2744`), `1 files · +87 · −0` (PR detail, `PullRequests.tsx:407`) — no pluralization.
- PR breadcrumb renders `strand › ·` with a dangling separator when there is no second segment.
- PR detail meta says `1d Ago` (title-cased "Ago").
- Worktree card shows `104.2 GB` — almost certainly counting `target/` + `node_modules`; exclude ignored dirs or drop the size.
- Worktrees copy ("AGENT WORKSPACES", "Keep one AI task per worktree…") frames a general git feature as AI-only.
- Fake mac traffic-light colours (`#ff5f57`, `#febc2e`, `#28c840`, `chrome.css:128–134`) and Windows close-hover `#e81123` (`170–171`) are hardcoded — acceptable as OS constants, but tokens would let light mode tune them.
- Dead CSS: `.la-btn` (`features.css:203–220`), `.tk-*` syntax classes with light overrides (`275+`), `.sync-btn.primary` (`chrome.css:433`), `.side-divider` (`1068`), `.badge.muted` (`994`), duplicate `@keyframes spin` in `base.css:47` and `features.css:2698`.
- Copy-paste pairs that will drift: `RailContextMenu` ≈ `TabContextMenu` (`RepoRail.tsx:175–234` / `RepoTabs.tsx:242–301`), `RailAddButton` ≈ `RepoSwitcherButton` (`RepoRail.tsx:241–358` / `RepoTabs.tsx:391–510`).

## 4. Suggested order

1. Diff surface theming (#2) and the Heroi composer / header overflow fixes (#15) — small, visible, fast.
2. `PaneHeader` + `EmptyState` + `DiffChrome` primitives (#1, #5, #16), migrating views one at a time.
3. `Dialog` primitive (#19).
4. Token sweep of `features.css` (#3, #4, #6) — mechanical, best done after the primitives exist so there is less to sweep.
5. Topbar / status-bar de-duplication (#7–#9) — needs a product decision on where branch / sync lives.
