# Strand 1.0.0

> Release-note source for `v1.0.0`. Publish only after every required row in
> [`docs/release-checklist.md`](../release-checklist.md) has evidence.

Strand 1.0 is the first stable release of the fast, keyboard-first Git client
built for reviewing agent-written code. It combines whole-context review,
parallel worktree workflows, and a complete everyday Git client without product
telemetry, feature gates, or a separate Strand account.

## Highlights

- **Agent review as a first-class workflow.** Pin a baseline, review committed,
  staged, and unstaged work as one queue, mark files reviewed, leave anchored
  notes, and copy precise feedback back to the agent.
- **Parallel attempts without cleanup anxiety.** Worktrees show activity,
  ahead/behind, dirty state, and disk use; compare several attempts side by
  side, merge the winner, and archive removed worktrees for restoration.
- **Cross-repository workspaces.** Group a product's repositories, import VS
  Code workspaces, and review the whole product through one merged queue.
- **Subscription-first AI writing.** Use a signed-in Codex or Claude Code CLI
  to suggest commit messages and pull-request drafts. Context is bounded,
  sensitive-file matches require a decision, generation is cancellable, and
  provider prompts are not retained by Strand.

## Everyday Git

- Stage or discard files, blocks, contiguous line ranges, or arbitrary changed
  lines; commit with amend, sign-off, and optional signing.
- Initialize, open, clone, and manage repositories, remotes, upstreams,
  branches, tags, stashes, submodules, and worktrees.
- Fetch, pull, push, sync, prune, select pull strategies, use autostash, push
  tags, and force-push only with a lease and explicit confirmation.
- Search full history, inspect reflog and file history/blame, compare commits or
  refs, verify commit signatures, export exact patches, and perform ordered
  multi-commit cherry-picks.
- Run merge-preserving interactive rebases with pick/reword/edit/squash/fixup/
  drop, resolve conflicts in a three-way editor, and continue or abort paused
  operations without leaving Strand.
- Run cancellable integrity checks, incremental maintenance, or guarded garbage
  collection with a bounded per-repository activity log.

## Hosted pull requests

GitHub and Azure DevOps Services/Server share one pull-request workspace:
search and follow pull requests, inspect commits/files/checks/activity, comment
on exact line ranges, batch reviews, edit or dismiss review state where the
provider allows it, close/reopen, merge, and open the exact provider head in a
worktree. Authentication stays in `gh`/`az`; only the optional Azure DevOps
Server PAT is stored by the operating system credential vault.

GitLab, Bitbucket, deeper pagination, and the remaining Azure thread-lifecycle
expansion are intentionally post-1.0 work.

## Desktop, trust, and performance

- Native desktop menus, rebindable global shortcuts, keyboard loops, focus
  traps, screen-reader labels, announced status, light/dark/system themes, and
  eight accent colors ship across macOS, Windows, and Linux.
- The production app uses a restrictive CSP and exact Tauri capability list.
  Stable updater metadata is signed and pinned to HTTPS; Linux AppImages also
  receive a GitHub-OIDC-bound Sigstore bundle.
- No product telemetry is collected. Crash reporting is local-first and
  user-mediated through a pre-filled GitHub issue that the user reviews before
  submitting.
- The measured engine opens the 100k-commit fixture in about 47 ms and refreshes
  the 10k-file status fixture in about 42 ms; methodology and caveats live in
  [`docs/perf-baseline.md`](../perf-baseline.md).

## Install and update

The release workflow produces a universal macOS DMG, Windows MSI, Linux `.deb`
and `.rpm` packages, and a Linux AppImage. The in-app stable updater covers the
macOS app bundle, Windows MSI, and AppImage; `.deb`/`.rpm` installs update
through the package manager.

Before publication, the release checklist requires notarization/signature
verification on every artifact, a real-platform smoke matrix, an end-to-end
update rehearsal, and hash/updater-manifest review. The repository does not
substitute cross-compilation for that evidence.
